# Event B controlled reproduction

## What was reproduced

Event A used a fixed VS Code Copilot workflow in Ask mode to add one feature
to each high- and low-debt variant. The saved run notes show that the feature
was implemented by extending an existing type and delegating existing
validation through `super`.

Event B repeats that feature shape against the modernised parents:

| System | Feature | Reuse decision |
|---|---|---|
| Booking | `ComputerClassRoom` | Extends `ClassRoom` and delegates booking validation to `super.book(...)` |
| Tickets | `TicketTypeSeasonalRestricted` | Extends `TicketTypeSeasonal` and delegates season/zone validation to `super.isValidFor(...)` |

The modernised feature classes use descriptive names and the parent equality
contracts from the Event B modernisation. No new superclass or design pattern
was introduced.

## Results

| System | Modernised files before | Modernised files after | Added files | Modified files | Build |
|---|---:|---:|---:|---:|---|
| Booking | 7 | 8 | 1 (`ComputerClassRoom.java`) | 0 | PASS |
| Tickets | 10 | 11 | 1 (`TicketTypeSeasonalRestricted.java`) | 0 | PASS |

This indicates that the same extension-based feature remained local to one new
source file after modernisation. The Event A runs also added one feature class
per scenario, but their saved source comparisons should be interpreted
separately because they were generated by the historical Copilot sessions.

## Limitation

This is a controlled source reproduction of the recorded Event A implementation
shape. It is not a new Copilot interaction: the historical VS Code session,
model selection, and prompt execution are not callable from this repository
script. The result therefore tests whether the documented reuse strategy fits
the modernised design, not whether a newly sampled AI response would be
identical.
